Open protocol concept

Proof of Testing

Contributor-side CI with cryptographic receipts. The harness runs your test suite on its compute and attaches a signed, publicly logged proof to the PR. You verify in milliseconds. You pay for zero CI.

Read the spec Break it
No hardware on Earth proves execution on a stranger's laptop. PoT doesn't pretend otherwise. It makes a false "tests passed" claim falsifiable, publicly attributable, and economically suicidal — the foundation CI trust already stands on, made explicit and machine-checkable.

The moment

curl killed its bug bounty — AI slop. Jazzband shut down — AI slop. GitHub is drafting per-repo PR kill switches. Maintainers burn CI money and attention on changes nobody provably tested.

Every AI coding agent already runs your tests — it must, to know its patch works. The green run exists. Today it's thrown away. PoT turns it into evidence.

The physics

Signatures prove who, never what

DSSE + Sigstore + Rekor: non-repudiable, identity-bound, timestamped. No signature ever proves the process executed.

Consumer hardware attests nothing

SGX is gone from consumer chips. Apple exposes nothing. TPMs see boot state, not userspace. zk-proving a real suite: 10⁴–10⁶× overhead, no syscalls.

"Tests passed" is a cache entry

Bazel hit this exact wall: an input-addressed cache entry is unverifiable from the value alone. Their answer was trusted infra.

Our answer

Determinism makes lies falsifiable. Identity + transparency logs make them attributable. Spot-checks + standing make them ruinous.

The protocol

  1. The repo defines a test contract

    .pot/contract.toml: exact command, runner container pinned by image digest, network off, determinism level. It lives inside the attested git tree — swap in a weaker contract and the hash under review changes.

  2. The harness runs it hermetically, builds a Merkle transcript

    Pinned container, stripped env, no network. Results become a canonical sorted list of (test_id, status), hashed into a Merkle tree. Any single test is later checkable against the signed root — no full re-run required.

  3. A real identity signs, in public

    in-toto Statement, DSSE envelope. Subject = git tree hash — the exact resulting code state, not a diff. Signed keylessly via Sigstore against the contributor's GitHub identity, logged in Rekor, append-only and public. No key management. No backdating. No taking it back.

  4. The maintainer verifies in milliseconds

    Six pure computations: signature ✓ identity ✓ tree == PR head ✓ contract digest ✓ freshness ✓ all green ✓. No test execution. No CI bill.

  5. Truth is enforced

    Random spot-checks — re-run a random Merkle shard; rate set by the identity's standing. Cross-submitter agreement — independent attestations of the same tree corroborate free; divergence bisects to one test. Canaries — branches with a planted failing test; attest one green and you've published proof you sign without running.

Standing — a credit score for contributions

Every identity carries a standing score: FICO for code, with one difference that changes everything — no bureau. Standing is a pure function over public data (the Rekor log, git histories, published fraud proofs). Anyone recomputes any identity's score from the same inputs and gets the same number.

EventStanding
Attestation spot-checked and matchedstrong + — verified truth is the only heavyweight earner

Two signature chains converge on one identity: GPG/SSH-signed commits prove who wrote the code; signed attestations prove who claims it's green. Standing prices how much anyone believes them. High standing buys low spot-check rates and cheap merges. One caught lie ends the identity — and the fraud proof travels to every repo that honors the log.

Farming is priced out by construction: standing earned in a repo is weighted by that repo's own standing (self-owned farms earn nothing), corroboration between clique members is discounted toward zero, scores decay, and earning requires someone else's verified compute. Full analysis in CONCEPT.md §13.

Verification is mining

Standing is mined by re-running other people's claims. Pick any claim from the public log, execute its tree under its contract, publish your root. Match — the claim gains confirmation weight, you earn standing. Divergence — the Merkle trees bisect to the lying test, the loser takes the slash, and you take a jackpot. A zero-standing identity bootstraps this way: no permission needed, just compute and honesty.

That's the consensus algorithm: per-claim, standing-weighted quorum by independent re-execution. No global chain, no fork choice, no token — hash-power is useful test execution, stake is identity history. Repos set a confirmation-weight threshold; consensus prices the verification, the maintainer keeps sovereignty.

Free-riders — copy the root, sign "confirmed", burn no compute — get eaten by forced errors: the protocol continuously publishes bait claims with wrong roots. Confirm bait and you've proven you mirror-mine. Bait is indistinguishable from real claims without running the tests, so the only safe mining strategy is the honest one. Fresh trees in merge queues use commit-reveal: nothing to copy. Spec: CONCEPT.md §14.

The economics

Honesty costs one containerized run plus a signature — the tests already ran to build the patch. Cheating costs the identity: a signed, logged, portable confession and a standing score that never recovers. The gradient does the enforcement.

The trust ladder

PoT-0Claimed. Signed attestation, verified identity, Rekor-logged. Attribution — already beyond "tests pass 👍".
PoT-1Contracted. Hermetic pinned run + contract binding + Merkle transcript. Falsifiable by any re-run.
PoT-2Checked. Standing-tiered spot-checks, canaries, cross-submitter log. Quantifiable assurance.
PoT-3Attested execution. TEE run (TDX / SEV-SNP / Nitro), reproducible runner image, hardware quote, in-enclave-signed verdict. Cryptographic proof, contributor-paid, cents per run.
PoT-4Proven. zkVM proof of the run — zero trusted parties. The ladder's defined top; waiting on proving costs.

One attestation format across every rung. A repo tightens its requirement with one line of policy.

Out of scope, by design: malicious code with genuinely green tests. PoT proves "the contract ran green" — never "the code is good." It replaces the CI bill, not code review.
