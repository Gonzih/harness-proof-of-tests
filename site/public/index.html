Concept & request for contributions

Proof of Testing

A protocol for open-source maintainers to stop paying for CI on contributors' PRs. The contributor's AI harness runs your test suite on their compute and attaches a verifiable, signed, publicly logged proof that it was green. You verify in milliseconds.

Read the spec on GitHub Open an issue
The honest one-liner: you cannot cryptographically prove execution on a stranger's laptop with today's hardware — but you can make a false "tests passed" claim falsifiable, publicly attributable, and economically irrational. Which is what CI trust already rests on.

The problem

AI harnesses are flooding open source with PRs. curl killed its bug bounty over submission slop; Jazzband shut down; GitHub is publicly weighing per-repo PR kill switches. Maintainers are being asked to spend CI money and review time on changes nobody has provably tested.

Meanwhile every AI coding agent already runs your tests — it has to, to know its patch works. The green run exists. It's just thrown away instead of being turned into evidence. PoT is the protocol for keeping it.

What is actually provable

Three research findings constrain every honest design in this space:

Signatures prove who, never what

DSSE + Sigstore + Rekor give a non-repudiable, identity-bound, timestamped claim. Nothing in any signature proves the test process executed.

Consumer hardware can't attest workloads

SGX is gone from consumer chips, Apple exposes nothing, TPMs see boot state not userspace. zk-proving a real suite is 10⁴–10⁶× overhead with no syscall support.

"Tests passed" is a cache entry

Bazel adjudicated this exact problem: an input-addressed action-cache entry is unverifiable from the value alone. Their answer was trusted infra. Ours is different.

So: don't chase impossible proof

Make lying falsifiable (determinism), attributable (identity + transparency log), and irrational (spot checks + reputation). Reproducible-builds logic, applied to tests.

How it works

  1. The repo defines a test contract

    You commit .pot/contract.toml: exact command, runner container pinned by image digest, network off, determinism level. It lives inside the git tree being attested — swapping in a weaker contract changes the hash under review.

  2. The harness runs it hermetically and builds a Merkle transcript

    Final run in the pinned container, stripped env, no network. Structured results become a canonical sorted list of (test_id, status), hashed into a Merkle tree — so any single test's result can later be checked against the signed root without re-running the suite.

  3. The claim is signed by a real identity, in public

    Standard in-toto Statement in a DSSE envelope. Subject = git tree hash (not the diff — the exact resulting code state). Signed keylessly via Sigstore: OIDC login as the contributor's GitHub account → ephemeral Fulcio cert → signature logged in Rekor, a public append-only transparency log. No key management; no backdating; no denying it later.

  4. The maintainer verifies in milliseconds

    Six pure computations: signature valid → identity acceptable → attested tree == PR head → contract digest matches the contract in that tree → Rekor timestamp fresh → zero failures. No test execution. No CI bill.

  5. Truth is enforced, not assumed

    Random spot-checks — re-run a random Merkle shard; rate scales with the identity's track record (new accounts: 100%). Cross-submitter agreement — independent attestations of the same tree corroborate each other for free; divergence is an automatic alarm that bisects to one test. Canaries — occasional branches with a deliberately failing test; anyone attesting them green just published proof they sign without running.

Why the economics hold

An AI harness must run the tests anyway to iterate — honesty costs one extra containerized run plus a signature. Cheating means forging claims against a system built to eventually catch you, where getting caught produces a portable, signed, transparency-logged confession tied to a GitHub identity forever. The identity's standing is the stake; no tokens, no blockchain beyond the existing public logs. Protocols win when the incentive gradient points the right way, not when lying is impossible.

The trust ladder

PoT-0Claimed. Well-formed signed attestation, verifiable identity, Rekor-logged. Attribution only — already better than "tests pass 👍".
PoT-1Contracted. Hermetic pinned run + contract binding + Merkle transcript. The claim is now falsifiable by any re-run.
PoT-2Checked. Active enforcement: tiered spot-checks, canaries, cross-submitter log. Probably true, with quantifiable assurance.
PoT-3Attested execution. Run in a TEE (Intel TDX / AMD SEV-SNP / Nitro) with a reproducibly built runner image; hardware quote + in-enclave-signed verdict. Cryptographic proof, contributor-paid, ~cents per run.
PoT-4Proven (future). zkVM proof of the run — no trusted party at all. Architecturally blocked today; the ladder's defined top as proving costs fall.

Same attestation format at every rung — a repo tightens its requirement with one line of policy, no redesign.

Threat model, condensed

AttackCountered by
Fabricate "green" without runningFalsifiability + spot-checks + canaries; permanent attributable fraud proof
Run a weakened suite / wrong commandContract digest lives inside the attested tree; command & image matched verbatim
Attest a stale or different treeSubject = tree hash checked against PR head; Rekor freshness window
Cherry-pick a lucky flaky runMaintainer-controlled quarantine list; divergence on any other test = alarm
Sybil fresh identitiesNew identities are spot-checked at 100% until they earn a history
Backdate / deny a claimAppend-only Rekor log; optional OpenTimestamps anchor
Out of scope, on purpose: malicious code with genuinely green tests. PoT proves "the contract ran green" — never "the code is good." It replaces the CI bill, not code review. Review stays; it just stops being a free CI service for strangers.

This is a request for contributions

Everything above is a concept backed by three research briefs (attestation ecosystem, trusted execution & verifiable compute, trust models & prior art) — all in the repo. Every component ships today: cosign, Rekor, in-toto's existing test-result predicate, OCI digests. The composition does not exist. Trustix, the nearest blueprint, is dormant. That's the gap.

Where help is wanted:

  • Poke holes in the threat model. Especially the flaky-test surface and Sybil economics. Adversarial reviews are the most valuable PR right now.
  • The pot CLI MVP — run / verify / spot-check as a single static binary over cosign + Rekor. Spec is in CONCEPT.md §10.
  • Transcript canonicalization per test framework (pytest, cargo test, go test, jest…) — the boring part that decides whether determinism level "status" works in the wild.
  • Harness integrations — a Claude Code / Codex hook: "repo has .pot/ → run pot run before opening the PR."
  • Quantitative deterrence. Nobody knows the right spot-check rates or the real base rate of fraudulent attestation. Modeling, simulation, or just instrumented reality — all wanted.
  • PoT-3 runner image — reproducible TEE runner for TDX/Nitro with in-enclave verdict signing.
